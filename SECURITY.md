# Security

Last reviewed November 19, 2026 for version 1.0.0 build 2.

The Windows desktop editor displays its interface in Microsoft Edge WebView2. A narrow communication bridge connects that interface to native operations such as file dialogs. The host checks the editor origin and uses session-scoped capabilities for native requests. It blocks navigation away from the local editor, cancels child-frame navigation and unsolicited new windows, and denies permission requests apart from the explicitly allowed local download case. Imports, project paths and recognized link protocols are validated. Imported source, custom code and external media still require review before use.

The optional online AI tools use Google Gemini, Google's artificial intelligence service. An API key is the secret credential identifying the Google project that may make requests; it is separate from the website project being edited. Save key stores it in Windows Credential Manager for the current account. New project files and exported websites exclude that credential, and Google requests authenticate in a header rather than a URL query string. Legacy browser/project credentials can remain until explicitly removed; see [privacy](docs/PRIVACY.md).

Gemini previews require the user's free-tier and sharing confirmations. Billing must be disabled on the key's Google project; the app cannot verify that setting. Requests are bounded, cancellable and limited to the selected operation's listed context. Named-section targeting is resolved locally before a credential read or request, and proposed operations are checked again before an atomic, undoable Apply. The assistant cannot execute generated code, configure contact-delivery endpoints, publish, upload or send email. Selected wording can still be private, and Google may use free-tier content to improve its products. See [Gemini assistant](docs/GEMINI_ASSISTANT.md).

SFTP (SSH File Transfer Protocol) uploads website files over an encrypted SSH connection. The user's SSH key authenticates the account, while the server's host key identifies the destination. The workflow strictly checks the user-supplied trusted-hosts file before connecting. Native child processes have bounded waits and are terminated with their owning job. Transfer requires a destination scan, backup, reviewed changes and confirmation; journals and receipts support recovery from partial failure. Earlier loopback checks passed in both architectures. No production server, live form or email recipient was used in the November 18 validation.

On November 18, full source/API/test lint, TypeScript, Vite, both native Release builds and 447 regression tests passed; two pre-existing optional integration checks were skipped. A separate request to npm's registry bulk advisory API covered all 322 locked package names and their recorded versions, including development dependencies, and returned zero advisories. This is a dated known-advisory result, not an independent penetration test or a guarantee against unknown or future vulnerabilities. Earlier Package Studio lifecycle checks exercised extraction paths, file ownership, upgrade rollback, durable uninstall and preservation of unrelated or modified files. The Microsoft WebView2 loaders have valid Microsoft signatures; the application and installers remain unsigned.

The optional legacy serverless `api` handlers are excluded from desktop installers and exported websites. Hosting them requires separate authentication, authorization, quotas and service credentials. Copying this repository to a public server does not provide those controls. The site checker reports specific content and link findings; it does not certify accessibility or overall site safety.

Never commit credentials, private projects, keys, model weights or personal site exports. Report vulnerabilities privately to the repository owner and keep secrets and private project files out of public issues. Owner installation observations are recorded in the [release review](docs/RELEASE_1_0_REVIEW.md); no fresh-Windows VM test, independent security assessment or provider-specific public deployment was performed for this update.

Optional TAtlas website translation uses the same GTranslate website widget as the Atlas website. It loads GTranslate only in exported pages and their separate browser review, without translating the editor interface. No vendor script is added to the privileged WebView2 editor or its React canvas. Exports with the packaged translation helper receive a narrowly scoped local-review connection allowance for `https://translate-pa.googleapis.com`; other reviews retain `connect-src 'self'`. Local-review form submission and framing protections remain in place. The feature requires external service access, sends page text for translation and uses the provider's current terms; it does not use a saved Gemini key. See [website translation](docs/WEBSITE_TRANSLATION.md).

Local test-folder refresh accepts a destination selected by the native Windows folder dialog. Reviewed website ZIPs are checked for traversal, collisions, reparse points, size limits and project ownership before use. Existing affected files are backed up and verified before replacement. Only previously managed files can become obsolete removals; unrelated files are preserved. Failed writes trigger recovery, while files changed concurrently by another editor require separate recovery rather than silent replacement. A folder preview serves a whitelist of visitor files over loopback and excludes its private manifest and unrelated contents. See [local site testing](docs/LOCAL_SITE_TESTING.md).

The Windows external-link checker requests webpage response headers using HTTP or encrypted HTTPS. It resolves a destination's domain name through DNS (the Domain Name System), checks that the returned network addresses are public, then pins the validated address for the connection. DNS lookups and requests have time limits, and redirects receive the same address checks. Hostname and certificate verification remain enabled; unsupported Windows behavior produces an unverified result.

The checker uses standard web ports without authentication or cookies and inspects only response headers. Confirmed missing pages are distinguished from restricted or inconclusive checks. A successful response does not establish that the destination's content is correct or safe, and these controls do not certify the editor as free of vulnerabilities.
